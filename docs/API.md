# API contract v1

Base URL `http://localhost:8000/api`. JSON, camelCase. Money is always `{ "amount": "8954000.00", "currency": "KRW" }` (decimal string, ISO 4217). Times are ISO 8601 UTC strings. IDs are prefixed strings (`pay_…`, `mdt_…`).
The backend serves the generated OpenAPI at `/api/openapi.json`; the frontend generates its types from it (`openapi-typescript`). **This document is the agreement; the OpenAPI is the source of truth for exact fields.** Breaking changes: the backend appends an entry to "Changelog" at the bottom and keeps the old field for one round when possible.

Errors: `{ "error": { "code": "POLICY_DENIED", "message": "…", "ruleId": "LX-03", "details": {} } }` with a proper HTTP status. Codes are stable; the web app translates them.

| GET | `/clock` | → `{ now, simulated: boolean }` |

`Account = { id, bank: "Lotus Home Bank (MOCK)", currency, maskedNumber: "•••• 4821", balance: Money }`

## Passkeys (WebAuthn)

| Method | Path | Notes |
|---|---|---|
| POST | `/webauthn/register/options` | → PublicKeyCredentialCreationOptionsJSON |
| POST | `/webauthn/register/verify` | `{ credential }` → `{ ok }` |

## Agent

| Method | Path | Notes |
|---|---|---|
| POST | `/agent/threads` | → `{ threadId }` |
| GET | `/agent/threads/{id}` | → `{ threadId, messages: AgentMessage[] }` |
| POST | `/agent/threads/{id}/messages` | `{ text?, documentIds?: string[], locale }` → **SSE stream** of `AgentEvent` |

`AgentEvent` (SSE `event:` = `type`):
- `token` `{ text }` — streamed assistant text
- `step` `{ id, label, status: "running"|"done"|"failed", tool?: string }` — visible plan/progress ("Verifying payee credential…")
- `card` `{ kind: "quote"|"payee"|"pack"|"approval_required"|"blocked"|"refund"|"info", data }` — rich cards rendered inline
- `envelope` `{ envelopeId, action, requestedTier }`
- `disposition` `{ envelopeId, result: "DENY"|"ESCALATE"|"AUTO_EXECUTE"|"OBSERVE", ruleIds: string[], reasons: Reason[] }`
- `done` `{ messageId }` · `error` `{ code, message }`

`Reason = { ruleId, code, severity: "info"|"warn"|"block", params: {} }` (the web app renders localized text from `code` + `params`).

### v1.23 - Two public origins and authenticated proxy IPs (20 October 2026)

Passkey endpoints select the RP hostname from the request's exact `Origin` in the configured comma-separated `WEBAUTHN_ORIGIN` allowlist. For the public test, allow `https://bursarbridge.noamofficial.vn` and `https://bursarbridge.pages.dev`; their RP IDs are their respective hostnames. Host, X-Forwarded-Host and credential payloads cannot add an origin or select another RP. Unknown, empty, null or duplicate Origin headers return 403 `WEBAUTHN_ORIGIN_NOT_ALLOWED`. Non-browser clients without Origin use the first configured origin; keep the old host first for compatibility. Local defaults remain localhost origins on 3000 and 3700, both RP localhost.

Registration/assertion challenges and the short-lived assertion receipt bind one exact origin/RP pair. Verification or receipt consumption through another origin fails, including when the consent hash is the same. Credentials are stored per user/RP. Existing legacy credentials are tagged with the existing `WEBAUTHN_RP_ID`, which must stay set to the old host during upgrade; adding a Pages passkey cannot replace the old one. Existing mandates and approvals are unchanged. Pending ceremonies/receipts created before this upgrade need fresh options/verification. Register a separate passkey on the new domain; cross-domain passkey sharing is not claimed. JSON request/response fields are unchanged; options' rp.id/rpId now reflect the selected domain.

In public mode, `X-BB-Client-IP` is used for every IP-based admission/message/write limit only when a single `X-BB-Proxy-Secret` matches the nonempty `PUBLIC_PROXY_SECRET` env value via constant-time comparison. The IP must be one valid IPv4/IPv6 literal, not a chain, port, CIDR or zone. Missing/wrong/duplicate secret, duplicate IP or invalid IP retains the existing trusted-loopback/Uvicorn client resolution. The shared secret grants no session or payment authority and is never returned or logged by the API. Empty/unset env disables this override. The proxy must overwrite these headers and forward the browser's Origin unchanged; API secrets belong only in private API/worker configuration, never a web build.

Bootstrap keeps relative 303 Location values and Secure/HttpOnly/SameSite=Lax host-only cookies. API download URLs remain relative. Each public hostname therefore keeps its own browser cookie/sandbox; opening the second hostname does not join or reset the first host's family. No public hostname switch, redirect, cookie-domain rewrite, live env edit or live restart is performed by this change. The Pages proxy must pass through relative redirects and Set-Cookie without following the bootstrap redirect at the origin.
