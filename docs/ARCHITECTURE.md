```

services/api/        Python 3.12 FastAPI app: agent, policy engine, mock rails, evidence — owned by the backend builder

```

                                        │
                                        ├── Agent (LangGraph): intent, extraction, planning, explanation
                                        │       emits governance envelopes only; never holds credentials
                                        ├── Policy engine (pure Python, versioned YAML rules, rule IDs)
                                        │       ordered checks → DENY / ESCALATE / AUTO_EXECUTE / OBSERVE
                                        ├── Mock Home Bank (VND/CNY ledgers, FX board, quotas, outbound packs, grants, cancel)

## Decisions (builder may push back with reasons)

- **LLM**: provider adapter, Anthropic or OpenAI chosen by env key; a deterministic `scripted` provider for tests/CI and for running the demo without a key. Money-relevant fields (payee, amount, destination) never come from LLM output; they resolve from credentials, mandates and bank records.
- **Storage**: SQLite via SQLModel (single file, reset per demo). Audit log is append-only JSONL + table mirror.
- **Chain**: FISCO BCOS 3.x 4-node Air chain in WSL2 Ubuntu, Web3 RPC (web3.py). If the chain cannot run by Sat 17 Oct 14:00 VN, fall back to anchoring in the local hash chain only and drop the bonus claim. Never fake hashes.
- **Passkeys**: WebAuthn (`@simplewebauthn/browser` on web, `webauthn` (py_webauthn) on API). The challenge for a payment approval is the consent hash. A "demo authenticator" fallback exists only behind an explicit DEMO flag and is labelled in the UI.
- **Realtime**: Server-Sent Events for agent streaming and app notifications.
- **i18n**: UI strings in the web app (next-intl), locales `en`, `ko`, `zh`, `vi`. API returns stable codes + English messages; the agent replies in the user's language.
- **Ports**: web `3000`, API `8000`, FISCO RPC `8545`, Watchman `8084`.

## Trust boundaries

1. Everything from documents, emails and chat is **untrusted data** (provenance `untrusted_doc` / `chat`). Tainted parameters force escalation; they can never become a payee.
2. The policy engine is the only component that can request a grant from the bank. The agent can only propose envelopes.
3. The parent's passkey signs the canonical consent hash; the bank re-derives it from the submitted instruction.
4. Refund destination is invariant: original payer account. Anything else is L-X.
5. No personal data on chain; per-user encryption keys off chain (crypto-shredding).
